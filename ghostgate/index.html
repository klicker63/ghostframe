01 / THE PROBLEM

A successful demo can still conceal unsafe behavior

Agents inherit risk from every instruction, tool, permission, and system they touch.

Normal task testing tells you whether the happy path works. It does not show what happens when a support ticket carries hidden instructions, a repository contains malicious context, a tool returns poisoned data, or an agent finds another path after a blocked action.

  • Prompt injection
  • Poisoned tool results
  • Permission confusion
  • Unsafe redirects
  • Encoded instructions
  • Fragmented data exfiltration
  • Draft-to-send escalation
  • Repeated blocked-action attempts
  • Cross-system abuse
  • Compromised support tickets
  • Malicious repository content

03 / WHAT GHOSTGATE EVALUATES

Behavior, boundaries, escalation, and recovery

The evaluation follows the action—not just the final answer.

01Tool-use behavior

What the agent proposes, invokes, or chains together.

02Permission boundaries

Whether access stays within the intended envelope.

03Approval handling

How the agent reacts to required, missing, or fake approval.

04Data access

What information is read, transformed, or moved.

05Escalation attempts

Direct and alternate paths toward higher-impact actions.

06Repeated unsafe behavior

Retries, reframing, and low-and-slow attempts after denial.

07Cross-system actions

How one tool or environment affects another.

08Recovery after blocks

Whether the agent stops, asks, adapts safely, or routes around control.

09Poisoned context

Behavior when instructions or tool results cannot be trusted.

10Evidence completeness

Whether the run preserves enough context for review.

07 / PILOT BOUNDARIES

Clear limits are part of credible evaluation

What the current private-pilot model does—and does not—mean.

GhostGate is a local-first beta used in controlled private-pilot workflows. Adapter maturity varies, and some connections are sample or experimental. Evaluation quality depends on the selected scenarios, policies, agent configuration, and environment.

  • It evaluates defined behavior under controlled conditions.
  • It recommends permission boundaries; it does not certify compliance.
  • It can support production policy decisions; it does not guarantee safe production behavior.
  • It does not replace architecture review, penetration testing, monitoring, or incident response.
  • Universal framework integration is not claimed.
